# DESIGN-SYSTEM.md

> This is the visual contract. Implementation reads it; the visual gate verifies against it;
> the visual-reviewer agent critiques against it. Fill every section before writing UI stories.
> Vague design systems produce generic UIs — be specific and opinionated.

## 1. Aesthetic direction (commit to ONE)

Pick an extreme and state it in a sentence. Examples: brutally minimal, editorial/magazine,
retro-futuristic, organic/natural, luxury/refined, industrial/utilitarian, art-deco/geometric.

> **Our direction:** _e.g. "Refined editorial — generous whitespace, a characterful serif
> display face, one saturated accent, restrained motion."_

**The one unforgettable thing:** _what will a user remember? (a signature interaction, a
distinctive type treatment, a bold color move)_

## 2. Type scale

Avoid generic fonts (Inter, Roboto, Arial, system). Pair a distinctive display font with a
refined body font. Define an explicit modular scale — the gate checks computed sizes.

| Token | Font family | Size / line-height | Use |
| --- | --- | --- | --- |
| `type-display` | _e.g. "Fraunces", serif_ | 48/52 | hero, h1 |
| `type-h2` | display | 32/38 | section heads |
| `type-body` | _e.g. "Söhne", sans_ | 16/26 | paragraphs |
| `type-mono` | _e.g. "Berkeley Mono"_ | 14/20 | code, data |

## 3. Color tokens (these are quantum.json contracts — names are exact)

Dominant colors with sharp accents beat timid, evenly-distributed palettes. Provide light/dark.

| Token | Light | Dark | Notes |
| --- | --- | --- | --- |
| `color-bg` | | | page background |
| `color-surface` | | | cards, sheets |
| `color-fg` | | | primary text — must hit WCAG AA on `color-bg` |
| `color-muted` | | | secondary text |
| `color-accent` | | | the one saturated move |
| `color-accent-fg` | | | text on accent |
| `color-border` | | | hairlines |
| `color-danger` | | | destructive/error |

> Every fg/bg pairing here must pass contrast — the a11y gate enforces it.

## 4. Spacing & radius scale

Use a single scale; no magic numbers in components.

`space`: 4 · 8 · 12 · 16 · 24 · 32 · 48 · 64 · 96
`radius`: `radius-sm` 4 · `radius-md` 8 · `radius-lg` 16 · `radius-pill` 999

## 5. Motion

Define duration + easing tokens. Favor one well-orchestrated load (staggered reveals) over
scattered micro-interactions.

`motion-fast` 120ms · `motion-base` 240ms · `motion-slow` 480ms · easing `cubic-bezier(0.2,0.8,0.2,1)`
Respect `prefers-reduced-motion` (the a11y gate checks this).

## 6. Component conventions

For each shared component, define states so stories don't reinvent them:
- States to cover: default, hover, focus-visible, active, disabled, loading, error, empty.
- Focus rings are mandatory and visible (a11y gate fails on focus traps / invisible focus).

## 7. Responsive intent

Define what changes at each breakpoint (from `lens.config.json`): mobile 375, tablet 768,
desktop 1280. The visual gate screenshots all three; state the intended layout at each so a diff
is meaningful rather than noise.

## 8. Per-screen visual acceptance criteria (the gateable part)

For each screen/story, write criteria that map to a runnable check:
- [ ] Matches baseline screenshot at mobile/tablet/desktop within tolerance
- [ ] 0 axe violations at all breakpoints
- [ ] All text/bg pairs pass WCAG AA contrast
- [ ] Lighthouse a11y = 1.0, performance ≥ threshold
- [ ] Keyboard-only: every interactive element reachable with visible focus
